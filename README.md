# Локальный почтовый агент

Первая версия для Windows: Gmail + локальный сервер LM Studio + оконный интерфейс Tkinter.

Текущая версия: **0.7.0-alpha**. Состав версии, результаты проверок и ограничения: [TESTING.md](TESTING.md).

## Запуск

Из папки проекта в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

После установки зависимостей приложение также запускается двойным щелчком по `start.cmd`.

В LM Studio загрузите имеющуюся модель 4–8B, включите локальный OpenAI-compatible сервер. В приложении укажите адрес API (по умолчанию http://127.0.0.1:22227/v1) и точный ID модели (по умолчанию qwen3.5-4b).

## Gmail

Для подключения нужен собственный Google Cloud проект с включённым Gmail API и OAuth-клиентом типа Desktop app. Скачанный клиентский JSON поместите в `private/credentials.json`. Затем нажмите «Подключить Gmail» и войдите в браузере. Для проекта в тестовом режиме ваш Gmail должен быть добавлен в тестовые пользователи OAuth.

Токен доступа сохраняется в `private/token.json`; эта папка исключена из Git. Не публикуйте её и не передавайте другим. Письма передаются модели по указанному адресу API; для локальной обработки оставьте адрес loopback. Приложение также обращается к Google для работы с Gmail.

## Поведение первой версии

- Разбор запускается вручную партиями по 5 писем (настраивается до 500), включая старую почту. Отправленные письма, черновики, корзина и Gmail-спам исключены из разбора.
- Создаются метки `Agent/Вакансии`, `Agent/Конференции` и другие фиксированные категории. Обычные письма остаются во входящих. Карантин убирает письмо из входящих, но не удаляет его.
- Вложения сохраняются в выбранную папку, в подпапки по ID письма, до отметки письма обработанным. Для категории «Карантин» вложения не скачиваются и не сохраняются; оригиналы остаются в Gmail. Ранее сохранённые файлы автоматически не удаляются. После повторной классификации в обычную категорию вложения сохранятся. Файлы автоматически не открываются.
- Метка `Agent/Обработано` позволяет продолжать следующую партию без повторного разбора. Кнопка «Пересортировать по новым правилам» выбирает обработанные письма без метки `Agent/Правила-v2`. После успешного разбора эта метка добавляется: следующая партия продолжает переход на новые правила. Старые известные категории агента заменяются новой, пользовательские метки сохраняются. Для повторной проверки письма, уже обработанного по v2, удалите у него только метку `Agent/Правила-v2` в Gmail.
- «Безопасность» объединяет уведомления входа, двухфакторной аутентификации и паролей. «Вакансии» предназначена для найма; анонсы моделей и продуктов относятся к «Рассылкам». Эти правила задаются модели, поэтому точность необходимо проверять на письмах.
- Журнал в окне показывает тему, предыдущую и новую категорию и ошибки; он хранится до закрытия приложения. Неверный формат ответа модели оставляет письмо без изменений для следующей попытки. Вывод из карантина не возвращает письмо во входящие автоматически: это можно сделать вручную в Gmail.
- Модель пишет редактируемый черновик по заданию. Получателя, тему и файлы выбирает пользователь. Выбор файлов ограничен папкой сохранённых почтовых вложений. Отправка выполняется только после отдельного подтверждения.

## Следующие этапы

### Контакты и подготовка письма (этап 3)

Кнопка «Контакты и псевдонимы» открывает локальную адресную книгу `private/contacts.sqlite3`. Поддерживаются добавление, редактирование и удаление. Имя и псевдонимы вводит пользователь; сохранение подтверждает соответствие адресу. Импорт адресов из переписки пока не реализован. Совпадающие обозначения разных адресов считаются неоднозначными: приложение просит указать точный email.

«Написать черновик» теперь подготавливает получателя, тему и текст по запросу. Пустое поле получателя позволяет модели выбрать подтверждённый контакт из запроса. Заполненное поле (email, имя или псевдоним) имеет приоритет. При подготовке следующего письма очистите получателя, если хотите выбрать другого из запроса. Неизвестный адрес, отсутствующий в запросе и контактах, не принимается от модели. Ошибка формата ответа оставляет прежний черновик без изменений. Файлы по-прежнему выбираются вручную из почтовых вложений; список выбранных файлов передаётся локальной модели вместе с запросом.

Проверка этапа:

1. Создать контакт с собственным адресом и псевдонимом «тестовый контакт», закрыть и открыть окно контактов — запись должна сохраниться.
2. При работающей LM Studio очистить поле получателя, написать «Напиши тестовому контакту, что отчёт готов» и нажать «Написать черновик». Проверить адрес, тему и текст. В Gmail ничего не должно отправиться.
3. Создать второй контакт с другим адресом и тем же псевдонимом; указать «тестовый контакт» в поле получателя. Приложение должно сообщить о неоднозначности, не выбирая адрес самостоятельно.
4. При необходимости проверить отправку только на собственный ящик: просмотреть письмо, нажать «Проверить и отправить», сначала отменить подтверждение — отправки быть не должно. Реальная отправка происходит только после согласия.

Автоматические тесты подтверждают хранение контактов, изменение и удаление, разрешение псевдонимов, отказ при неоднозначности, проверку email и ответа модели, подготовку полей без отправки и отмену отправки. Проверка нового запроса на реальной LM Studio остаётся отдельной проверкой интеграции.

### Подбор вложений по запросу (этап 5)

Запрос «Напиши начальнику и приложи отчёт за сентябрь» позволяет модели сформировать поисковый запрос к локальному каталогу. Поиск учитывает слова в имени, содержимом, отправителе, теме и типе документа; е/ё считаются одинаковыми. При одном совпадении файл добавляется в список вложений черновика. При нескольких или отсутствии совпадений приложение просит уточнить запрос либо выбрать файл вручную; прежний черновик остаётся неизменным. Выбранные вручную файлы имеют приоритет. Кнопка «Убрать все вложения» очищает выбор перед новым письмом.

Перед поиском необходимо просканировать каталог. OCR во время подготовки письма не запускается автоматически. «Последний отчёт» при нескольких совпадениях требует уточнения: автоматический выбор по датам пока не реализован. Поиск буквальный, а не семантический; формы слов и неточная формулировка могут не совпасть. Перед фактической отправкой повторно проверяется существование файлов и принадлежность хранилищу; служебные скрытые файлы не допускаются.

Проверка на реальных файлах остаётся открытой до появления вложений в почте. Все текущие тесты используют синтетические документы и не отправляют письма. Проверка PDF/OCR на реальных пользовательских вложениях также отложена, поскольку подходящих файлов пока нет.

### Стиль из переписки (этап 6)

Переключатель «Учитывать стиль моих отправленных писем получателю» включён по умолчанию. После определения адресата приложение читает до пяти последних отправленных ему писем Gmail и дополнительно проверяет метку SENT и точный адрес в To. Используются только текстовые части без вложений, до 1200 символов из каждого письма; узнаваемые цитаты и подписи отсекаются. HTML-only письма пока не используются. Эти примеры не сохраняются отдельным файлом или в журнале.

Модель получает образцы для обращения, длины фраз и степени формальности; официальный тон обязателен. Старые факты, числа, подписи и инструкции из образцов не должны переноситься в новый текст. Соблюдение этого правила проверено на синтетическом примере, но требует просмотра черновика пользователем. При отсутствии истории, неподключённом Gmail или ошибке чтения используется обычный официальный стиль; причина видна в журнале. При выключенном переключателе история не читается. С примерами подготовка выполняет два обращения к модели и может занять больше времени.

Все текстовые обращения к модели теперь допускают только loopback HTTP-адреса; внешние адреса, HTTP-прокси и перенаправления исключены. Поиск истории — чтение Gmail, без отправки, изменения меток или скачивания вложений.

Следующие этапы: локальный голосовой ввод и обновление дизайна.

### Полный разбор необработанной почты (этап 7)

«Разобрать всю необработанную почту» собирает все доступные страницы Gmail с новыми и старыми письмами без метки `Agent/Обработано`, исключая Gmail-спам, корзину, отправленные и черновики. Поле «Писем за один запуск» задаёт размер страницы при полном разборе, а не предел общего количества. Сначала собирается список ID, затем начинается сортировка: это исключает пропуски из-за изменения меток между запросами страниц. Дубли ID исключаются. Новые письма, появившиеся после сбора списка, попадут в следующий запуск.

Прогресс и журнал показывают число писем и результаты. «Остановить разбор» работает и при сборе списка, и при сортировке; текущий сетевой запрос/письмо завершается, затем обработка останавливается. Успешные письма помечаются; следующий запуск продолжает оставшиеся. Некорректный формат ответа модели оставляет письмо необработанным, без бесконечного повтора в одном запуске. Сетевой сбой останавливает запуск с ошибкой; уже обработанные письма сохраняют отметки. Перед анализом повторно проверяются метки, чтобы пропускать письма, обработанные или перемещённые после сбора списка.

«Разобрать почту» по-прежнему разбирает одну ограниченную партию. Повторная классификация по новым правилам остаётся отдельным действием. Полный разбор читает много писем и может надолго занять модель. Проверка на реальном полном ящике выполняется пользователем после перезапуска; автоматические тесты используют поддельный Gmail API.

### Каталог вложений (этап 2)

Кнопка «Каталог вложений и поиск» открывает отдельное окно. «Сканировать хранилище» обновляет локальную базу `.catalog.sqlite3` в выбранной папке вложений. Повторное сканирование не дублирует записи; изменённые файлы перечитываются, удалённые скрываются. Это буквальный поиск по словам, без семантического поиска и без передачи документов модели.

Чтение содержимого поддерживает TXT, CSV, Markdown, LOG, DOCX и PDF. Текстовый слой PDF читается без модели; страницы без текста распознаются через локальную vision-модель LM Studio. PNG, JPEG, WebP, BMP и одностраничные TIFF также читаются через локальное OCR. Переключатель OCR находится в окне каталога; используются адрес и ID модели из главного окна. Требуется модель с поддержкой изображений (qwen3.5-4b проверена). OCR разрешён только на loopback HTTP-адресах, без внешних сервисов.

Лимиты: файл до 20 МБ, изображение до 25 млн пикселей, первые 20 страниц PDF, до 200 000 символов в индексе; первые 20 000 показываются в предпросмотре. Картинка для модели уменьшается до 2000 пикселей по большей стороне. Многостраничные TIFF, защищённые паролем PDF, XLSX и презентации пока не читаются. Смешанные страницы с текстовым слоем и картинками используют текстовый слой без дополнительного OCR картинок. Частичный разбор и ошибки явно показываются в статусе. После восстановления сервера повторное сканирование заново пробует неудачные файлы; успешный OCR кешируется. Результат OCR требует сверки с оригиналом. «Тип» — подсказка по ключевым словам, а не гарантированная классификация.

Новые сохранения дополнительно записывают имя, отправителя, дату, тему и ID письма в `.source.json`. У ранее сохранённых файлов источник неизвестен до повторного разбора исходного письма. «Показать файл в папке» выделяет его в Проводнике; файл автоматически не запускается. «Открыть исходное письмо» открывает Gmail в браузере (профиль /u/0 должен соответствовать подключённому ящику).

Автоматическая проверка: `.\.venv\Scripts\python.exe -m unittest discover -v`. Тесты используют временные файлы и поддельный Gmail API, не изменяют реальную почту.

Проверка пользователем после перезапуска:

1. Открыть каталог и нажать «Сканировать хранилище»; сверить файлы с папкой вложений.
2. Найти известное слово внутри TXT или DOCX, отсутствующее в имени файла; проверить показанный текст.
3. Повторить сканирование; количество записей не должно увеличиться без новых файлов.
4. Проверить выделение файла в Проводнике. Для нового сохранения проверить отправителя, тему и переход к исходному письму.
5. Для неподдерживаемого файла убедиться, что явно показан статус отсутствия чтения содержимого.

Этап считается проверенным на реальных данных после этих шагов. Автоматические тесты отдельно подтверждают сохранение и поиск, обновление и удаление записей, отсутствие дублей, обработку повреждённых файлов, границы хранилища, сохранение источника и пропуск вложений карантина.

Стиль из прошлой переписки, постоянный журнал и отмена сортировки, динамические категории, расписание, несколько ящиков и общая инфраструктура агента для будущего подключения к 1С пока не реализованы. При сортировке модель анализирует текст и заголовки писем. Каталог читает поддерживаемые документы локально, без модели. Подключение Gmail, сортировка и каталог проверены пользователем; новый этап контактов и черновиков требует проверки на реальных запросах.
